# latex — formal Markdown → PDF (LaTeX)

Produce a **serious, official technical document** as a PDF compiled with `xelatex`. Neutral, factual,
technical register; **zero decoration**. Full CJK. The deliverable is a print-grade `.pdf` plus its
`.md` source.

## When to use
- Technical solutions / schemes (技术方案), interface control documents (ICDs), specifications,
  RFC-style docs, 技术规范 / 标准 / 正式技术文档 that must be a polished, shareable, print-grade PDF.
- **NOT** marketing/pitch one-pagers → use `apple-sales-doc`. **NOT** a viewable web artifact →
  use `/check` (HTML) or `/open`.

## Style contract — default formal house style (apply by default; deviate only if the user explicitly asks)

**Register & content**
- Write it as a **pure technical document**: neutral, factual, declarative. State facts, options and mechanisms — nothing else.
- Be **genuinely technical**: name concrete protocols, components, data formats and mechanisms (e.g. log-based CDC, `upsert`/schema-drift handling, quantization AWQ/GPTQ/GGUF, PagedAttention, RBAC/ABAC, k-hop subgraph, metric store) — not hand-wavy prose.
- Where an input is unknown, present a **scenario table (分情况)** and mark values **"参考 / 待确认"** instead of guessing. Research may inform the *examples and emphasis*, but **do NOT put speculative inferences about the reader into the document** — write options and facts, not guesses about their situation.

**Omit unless the user explicitly requests it**
- **No AI-author trace, anywhere** — no "generated by / 由 AI 生成", no Claude co-author, no AI-slop phrasing. Set the PDF **Author metadata to the issuing org/person** (pass `AUTHOR=...`), never leave it blank-by-default or an AI name.
- **No document-control block, no version numbers, no document IDs, no dates-as-metadata, no "前言 / preface" filler, no revision history.** Keep the front matter to just the **title** (and a short neutral subtitle if useful).
- **No addressee line** ("致 XXX / To: XXX").
- **No specific person names** (authors, contacts, owners) — refer to teams by role if needed.
- **No commercial content in a technical doc**: no pricing / quotes (报价), no dedicated risk-register, no business/commercial sections. Keep to the technical scheme.

**Tone & framing**
- **No marketing / sales language, no flattery or gushing (肉麻), no self-promotion / vendor-capability pitch, no "对标 X" narrative storytelling.**
- **No unverifiable performance claims** (e.g. "数量级提升 / 10×"). If a number is not measured, do not state it as a selling point — defer to "以现场 / PoC 实测为准".
- **Do not disparage or negate other concepts, products or approaches** (e.g. "不是又一个中台 / 看板"). State the approach positively, on its own terms.
- **Refer to the client neutrally in the third person (客户)**; do NOT use second-person honorifics (贵司 / 贵公司 / 您).

**Structure**
- Numbered sections + a table of contents. Write **plain headings with NO manual numbering** — `执行摘要`, not `一、执行摘要` or `1.2 X`. `--number-sections` numbers them; manual prefixes cause double numbering. Cross-reference by section **name** ("见「私有化与合规」一章") to survive renumbering.
- CJK docs: the TOC title MUST read **目录**, not "Contents" (`build_pdf.sh` sets this automatically for CJK).

> **Specs/ICDs only (not the default):** if — and only if — the user asks for a normative specification or ICD, you MAY add a document-control block (Doc ID · Version · Status · Classification) and use **RFC 2119** keywords (MUST/SHOULD/MAY). For a technical solution/方案 (the common case) omit both and follow the house style above.

## Compile-safety (avoid page overflow / xelatex errors)
- Write comparison operators in ASCII — `<=`, `>=`, `->` — **not** `≤` `≥` `→` (glyphs may be missing from the mono/CJK font → tofu or breakage). Prefer Chinese words in prose ("不低于 / 不高于").
- Replace circled digits (①②…) and stars (★) with plain labels (`L1`, `【主体】`) — many fonts lack them.
- Keep tables to **≤ 4 columns**; move long prose out of cells. (A 5-column table? drop or fold a column — e.g. fold a leading "#" index into the first cell.)
- **Long monospace tokens (paths, keys, URLs) go in fenced code blocks, NOT table cells** — code blocks line-wrap (fvextra), table cells do not.
- Backtick or escape LaTeX-special characters in inline code.

## Procedure
1. **Write the body as Markdown** following the Style contract. Plain `#`/`##` headings (they become numbered sections + TOC). Do not hand-author a title block — pass Title/Subtitle as args.
2. **Compile** (set `AUTHOR` to the issuing org so the PDF has a real, non-AI author):
   ```bash
   AUTHOR="<Org>" bash ~/.claude/skills/latex/build_pdf.sh <in.md> <out.pdf> "<Title>" "<Subtitle>"
   # DocID/Version are the 5th/6th args — OMIT them for the default house style (they add a meta line + header id).
   # Override the footer classification if needed, e.g. FOOTER="商业机密 · Commercial-in-Confidence".
   ```
3. **VERIFY before delivering (self-check).** Render pages to PNG and **Read the images** — the title page (confirm: no doc-control/meta/addressee, real Author) **and** a dense table page (confirm: no overflow/tofu, TOC says 目录):
   ```bash
   pdftoppm -png -r 96 <out.pdf> /tmp/lpg   # then Read /tmp/lpg-1.png and a table page
   ```
   Also `pdfinfo <out.pdf> | grep -iE 'author|title'` to confirm Author = the org (never an AI). If anything overflows or a rule is violated, fix the markdown and recompile. Iterate until clean.
4. **Deliver** the `.pdf` path. Keep the `.md` source (and `.latex-header.tex` if customized) beside it so the doc can be revised + recompiled.

## Dependencies (check first; instruct the user if missing — do not silently fail)
- **pandoc** — `brew install pandoc`
- **TinyTeX (xelatex)** — install from https://yihui.org/tinytex/ , then: `tlmgr install fvextra fancyhdr sectsty lineno footnotehyper xurl`
- **poppler** (for the verify step's `pdftoppm` / `pdfinfo`) — `brew install poppler`

## Notes
- `build_pdf.sh` auto-locates TinyTeX, picks a CJK serif (Songti SC → Noto Serif CJK fallback) and mono (Menlo), emits a numbered TOC, A4 with 2.4 cm margins, a header (Doc ID if given + page), a footer (classification via `FOOTER`, default "Draft"), monochrome code highlighting, and — for CJK docs — a **目录** TOC title. Set `AUTHOR` for PDF author metadata. Fonts override via `CJK_FONT` / `MONO_FONT`. Shell-stdlib only (no Python).
- **Pairs with `/check`**: use `/latex` for a formal **PDF**; use `/check` for a viewable **HTML** artifact.
